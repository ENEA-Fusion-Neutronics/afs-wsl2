# AFS on WSL2 (Debian 13)

The Microsoft WSL2 kernel (`6.18.x-microsoft-standard-WSL2`) has **no AFS client**
(`CONFIG_AFS_FS` and `CONFIG_AF_RXRPC` are off, there is no `openafs.ko`). Both clients can be
added **as modules only**, on top of Microsoft's own kernel image.

| Client | Module | Userland |
|---|---|---|
| **kafs** | in-tree client, built as modules from the WSL2 kernel source | `kafs-client` |
| **OpenAFS** | out-of-tree `openafs.ko`, built with DKMS in a container | 1.8.x backport `.deb`s |

Builds run in rootless, throwaway Podman containers; the distro is only touched by
`afs-setup.sh`, step by step.

## How it works (read this once)

1. **Modules must come from a VHDX.** `/lib/modules/<release>` is an overlay over a read-only
   modules VHD whose writable layer is a **tmpfs**: `.ko` files copied there vanish when the VM
   stops.
2. **The VHDX replaces the stock one, it does not add to it.** `kernelModules=` selects the single
   `kernel-modules` boot disk; Microsoft's stock `artifacts.vhd` is used only when the option is
   empty. So our VHDX contains the stock modules **plus** ours in `extra/`, with `modules.dep`
   regenerated by `depmod`.
3. **`kernel=` is mandatory too.** WSL refuses to start with `kernelModules=` alone ("Customised
   kernel modules were supplied without specifying a customised kernel"). `kernel=` points to a
   copy of Microsoft's own kernel image of the **same release**. Building a kernel is optional
   (`--kernel`, `--latest`; see below).

## Files

```
openafs-backports-podman.sh ──► ./openafs-debs/   client, krb5, libs + openafs-modules-dkms
wsl-modules-vhdx.sh ──────────► ./wsl-modules-<release>.vhdx   kafs + openafs modules
                                (+ ./kernel-<release>-built with --kernel / --latest)
afs-setup.sh                    guided install/config of ONE client on the distro
```

**`openafs-backports-podman.sh`** builds the OpenAFS `.deb`s from the Debian source (trixie/sid)
in a container. It picks the newest version whose `NEWS` claims support for your kernel and
versions it `…~bpo13+1`.

**`wsl-modules-vhdx.sh`** clones the exact kernel tag, enables the kafs options (aborting if
anything would become built-in), builds kafs and `openafs.ko` (DKMS, container only), checks
vermagic and symbol CRCs against the stock modules, then builds the VHDX with `mke2fs -d` +
`qemu-img` (no root). Options:

- `--only kafs|openafs`, `--layout flat|nested`, `--seed DIR`, `--force`
- `--kernel`: also compiles the kernel image as a build test, saved as `kernel-<release>-built`
  (not identical to Microsoft's, not boot-tested)
- `--latest` / `--target-tag TAG`: test a newer release (see below)
- `--kernel-suffix STR`: image name suffix (default `-built`)

**`afs-setup.sh`** has `check` and `status` (read-only) and `kafs`, `openafs`, `switch`: each step
shows the command and asks first (`-y` no prompts, `-n` dry run). It never leaves both clients
loaded.

## Quick start

```bash
cd <your clone of this repository>
./openafs-backports-podman.sh   # skip if you only want kafs
./wsl-modules-vhdx.sh           # first run builds the kernel tree (~11 min); later runs are fast
```

The VHDX script prints the manual steps, in short:

```bash
cp wsl-modules-<release>.vhdx /mnt/e/wsl/
cp "/mnt/c/Program Files/WSL/tools/kernel" /mnt/e/wsl/kernel-<release>   # typical path, check it
file /mnt/e/wsl/kernel-<release>     # must say: version <release>
```

`%UserProfile%\.wslconfig`, section `[wsl2]` (backslashes doubled), **both** lines:

```
kernel=E:\\wsl\\kernel-<release>
kernelModules=E:\\wsl\\wsl-modules-<release>.vhdx
```

Then `wsl --shutdown`, reopen WSL and set up one client:

```bash
./afs-setup.sh check
./afs-setup.sh kafs --cell example.org --sparse    # or: ./afs-setup.sh openafs --cell example.org
```

Test (cell `example.org`):

```bash
kinit user@REALM
aklog-kafs example.org     # kafs
keyctl show @s             # kafs: an rxrpc key must appear
aklog -d && tokens         # OpenAFS, instead of the two lines above
ls /afs/example.org
```

## When Microsoft updates the kernel (`wsl --update`)

`kernel=` and `kernelModules=` keep pointing to your **old** copies, so WSL stays on the old
kernel with the old modules, consistent but not updated. (Mixing a new kernel with the old VHDX
would break every module, including stock ones like `tun` and `ip_tables`.) To follow the
update:

1. Comment out both lines in `.wslconfig` and `wsl --shutdown`: you are on Microsoft's new
   kernel, without AFS.
2. Redo the procedure: `./wsl-modules-vhdx.sh` (re-run `openafs-backports-podman.sh` first if the
   OpenAFS source must follow the kernel), copy the new VHDX and the new stock kernel, set the two
   lines, `wsl --shutdown`.

`afs-setup.sh check` flags modules whose vermagic does not match the running kernel.

## kafs or OpenAFS?

| | kafs | OpenAFS |
|---|---|---|
| Tokens | `kinit` + `aklog-kafs` (rxrpc key in the keyring) | `kinit` + `aklog` (PAG) |
| `fs` command, PAGs | not available | yes |
| ACLs | `afs.acl` xattr (`getfattr`/`setfattr`) | `fs listacl` / `fs setacl` |
| Maintenance | in-kernel, `kafs-client` package | out-of-tree module + userland kept in sync |
| Cache | fscache + `cachefilesd` (optional) | `afsd` disk cache |

Both module sets live in the same VHDX but **only one may be loaded** (both register filesystem
`afs`); `afs-setup.sh` stops and unloads the other client first.

**kafs notes.** `kafs-check-config` reads the kernel's `/proc/net/afs/rootcell`, so it reports
"default cell is NOT set" until `kafs-client.service` has run (`afs-setup.sh kafs` starts it),
even when `/etc/kafs/client.d/<cell>.conf` is correct. `--sparse` removes the include of the
generic cellservdb, so `/afs` lists only the cells in use and `example.org` is found via AFSDB DNS
records.

**OpenAFS notes.** The backport version sorts below a `1.8.17~pre1-1` you may have, so
`afs-setup.sh` unholds and uses `--allow-downgrades`. Never install `openafs-modules-dkms` on the
distro (no kernel headers there); it is only a build input.

## Troubleshooting

| Symptom | Fix |
|---|---|
| WSL will not start: "kernel modules … without … customised kernel" | Add the `kernel=` line. |
| `check`: no AFS modules | Wrong `.wslconfig` paths (doubled `\\`?) or no `wsl --shutdown`. |
| `check`: vermagic mismatch, `Invalid module format` | VHDX built for another release: rebuild. |
| Container has no DNS | Prefix the build script with `AFS_WSL_NET=host`. |
| Output file exists | `--force` (both build scripts). |
| First VHDX build is slow | `--seed DIR` (a built tree: same tag, gcc-13). |
| Permission denied after `aklog-kafs` | Token in another keyring: start a `keyctl session`. |

Later VHDX builds are fast anyway: the kernel tree is cached in `~/.cache/wsl-modules`.

## Testing a newer Microsoft kernel (`--latest`)

`./wsl-modules-vhdx.sh --latest` (or `--target-tag linux-msft-wsl-X.Y.Z.N`) builds the newest tag
with your running major.minor, in a separate container and a separate cache
(`~/.cache/wsl-modules/test-<release>`). Because the kernel is built here too, **all** modules
come from the same build (no stock baseline needed): the output is a consistent pair
`kernel-<release>-built` + `wsl-modules-<release>.vhdx`. `--kernel-suffix STR` changes the
`-built` suffix (`""` drops it).

This is a **self-built kernel, not Microsoft's binary**. The script checks vermagic and symbol
CRCs against the build's own `Module.symvers`, but never boots the kernel. To try it, point
`kernel=` and `kernelModules=` at the pair, `wsl --shutdown`, then `./afs-setup.sh check`; to go
back, comment out the two lines. The OpenAFS `.deb`s are the ones already in `./openafs-debs`
(chosen for your running major.minor).

## Limitations

- **Flat layout is legacy.** Microsoft's stock VHD uses it, so it is the default, but the WSL init
  code warns that it will be removed in a future version. When that happens, rebuild with
  `--layout nested` (adds `linux-headers` and an empty `perf/`).
- Cleanup of build caches and images: `./wsl-modules-vhdx.sh clean -y`,
  `./openafs-backports-podman.sh clean -y`.
